Bootstrap Configuration (Pest.php)

Located in tests/Pest.php, this file configures the test base classes and bindings for Feature and Unit directories.

tests/Pest.php 
<?php

pest()->extend(Tests\TestCase::class)
    ->in('Feature', 'Unit');

API Feature Testing Patterns

Standard patterns for testing REST endpoints, tokens, roles, and JSON payloads.

Simulate authenticated users with specific roles without making live database network round-trips:

tests/Feature/AuthTest.php 
test('authenticated user can access profile', function () {
    $userType = UserType::firstOrCreate(
        ['user_type_name' => 'Admin'],
        ['user_type_name' => 'Admin']
    );

    $user = User::factory()->make([
        'id'           => 99999,
        'email'        => 'testadmin@example.com',
        'user_type_id' => $userType->id,
    ]);

    Laravel\Sanctum\Sanctum::actingAs($user);

    $response = $this->getJson('/api/me');

    $response->assertStatus(200)
        ->assertJson([
            'status' => true,
            'message' => 'User fetched',
        ]);
});

Ensure that sensitive endpoints trigger HTTP 429 Too Many Requests after threshold breaches:

Throttling Test Example 
test('login is rate limited after 6 attempts', function () {
    for ($i = 0; $i < 6; $i++) {
        $this->postJson('/api/login', [
            'email'    => 'throttletest@example.com',
            'password' => 'wrongpassword',
        ]);
    }

    $response = $this->postJson('/api/login', [
        'email'    => 'throttletest@example.com',
        'password' => 'wrongpassword',
    ]);

    $response->assertStatus(429);
});

Verify that users with non-privileged roles are strictly blocked from Tier-1 administration routes:

RBAC Test Example 
test('non-admin user cannot access user management endpoints', function () {
    $studentType = UserType::firstOrCreate(
        ['user_type_name' => 'Student'],
        ['user_type_name' => 'Student']
    );

    $user = User::factory()->make([
        'id'           => 99998,
        'email'        => 'student@example.com',
        'user_type_id' => $studentType->id,
    ]);

    Laravel\Sanctum\Sanctum::actingAs($user);

    $response = $this->getJson('/api/users');
    $response->assertStatus(403);
});

Verify that API requests always receive clean JSON error payloads instead of HTML stack traces:

JSON Exception Test 
test('unauthenticated request to protected route returns 401 json', function () {
    $response = $this->getJson('/api/me');
    $response->assertStatus(401)
        ->assertJson([
            'status'  => false,
            'message' => 'Unauthenticated. Please provide a valid Bearer token.',
            'data'    => null,
        ]);
});

Database Integrity & Transaction Testing

Testing database rollbacks, custom voucher sequence locking, and atomic multi-table inserts.

CNAT API uses transaction isolation to execute atomic operations (such as registering a student, generating an admission number, and creating an initial fee receipt). Testing these transactions ensures that any exception cleanly rolls back all tables.

Atomic Multi-Table Workflow Test 
test('can create student with admission and initial fee in one transaction', function () {
    $admin = User::factory()->make(['user_type_id' => 1]);
    Laravel\Sanctum\Sanctum::actingAs($admin);

    $payload = [
        'student' => [
            'student_name' => 'Rahul Sharma',
            'phone1'       => '9876543210',
            'gender_id'    => 1,
            'district_id'  => 1,
        ],
        'admission' => [
            'course_id'       => 1,
            'course_status_id'=> 1,
            'fee_modes_id'    => 1,
            'course_fees'     => 12000,
            'admission_date'  => '2026-09-01',
        ],
        'fees' => [
            'amount_paid'  => 3000,
            'payment_mode' => 'Cash',
        ]
    ];

    $response = $this->postJson('/api/admissions/admissionWithStudent', $payload);

    $response->assertStatus(200)
        ->assertJsonPath('status', true);

    $this->assertDatabaseHas('students', ['student_name' => 'Rahul Sharma']);
    $this->assertDatabaseHas('admissions', ['course_fees' => 12000]);
    $this->assertDatabaseHas('simple_fees_receipts', ['amount_paid' => 3000]);
});
Safe Database Isolation Rule

Always wrap live test cases modifying database state with Laravel's use Illuminate\Foundation\Testing\DatabaseTransactions; trait so all inserted rows are automatically rolled back at the end of each test method.

Pest 3.x Assertion Cheat Sheet

Quick reference for high-speed assertions in Pest and Laravel testing.

HTTP Response Assertions

$response->assertStatus(200);
$response->assertOk();
$response->assertCreated(); // 201
$response->assertUnauthorized(); // 401
$response->assertForbidden(); // 403
$response->assertNotFound(); // 404
$response->assertUnprocessable(); // 422
$response->assertTooManyRequests(); // 429

JSON Payload Assertions

$response->assertJson(['status' => true]);
$response->assertJsonPath('data.user.email', 'user@example.com');
$response->assertJsonStructure([
    'status',
    'message',
    'data' => ['token', 'user' => ['id', 'email']]
]);
$response->assertJsonCount(5, 'data');

Higher-Order Expectations

expect($value)->toBe(100);
expect($user->email)->toBeString()->toContain('@');
expect($array)->toHaveCount(3);
expect($user)->toBeInstanceOf(App\Models\User::class);
expect($fn)->toThrow(InvalidArgumentException::class);

Database Assertions

$this->assertDatabaseHas('users', ['email' => 'admin@cnat.com']);
$this->assertDatabaseMissing('users', ['email' => 'deleted@cnat.com']);
$this->assertDatabaseCount('students', 10);
$this->assertModelExists($student);
