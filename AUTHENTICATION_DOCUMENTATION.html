1. The Big Picture: What is API Authentication?

Unlike traditional websites where your browser saves cookies in a session, REST APIs are stateless. Every single HTTP request sent to the server must carry its own identification badge.

Novice Corner: The Hotel Keycard Metaphor

Think of how a modern hotel works:
• Login (POST /api/login): You present your username & password at the front desk.
• Token Creation: The desk clerk verifies who you are and gives you a magnetic room keycard (auth_token).
• Protected Endpoints (auth:sanctum): When you ride the elevator or open doors, you tap your card. You don't need to recite your password every time.
• Role Access (role:Admin,Owner): If a guest tries to tap their card at the "Staff Maintenance Room", the reader beeps red (403 Forbidden).
• Logout (POST /api/logout): When checking out, the system deletes your keycard code so it cannot open doors anymore.

public function register(RegisterRequest $request)
{
    try {
        $user = User::create([
            'email'        => $request->email,
            'password'     => Hash::make($request->password), // One-way bcrypt hash!
            'user_type_id' => $request->user_type_id,
            'employee_id'  => $request->employee_id,
            'student_id'   => $request->student_id,
        ]);

        $user->load(['userType', 'employee.department', 'employee.designation', 'student']);
        return ResponseHelper::success('User created successfully', ['user' => new UserResource($user)], 201);
    } catch (Exception $e) {
        return ResponseHelper::error($e->getMessage());
    }
}
3

User Login & Token Generation

POST /api/login

Validates input credentials, checks database connectivity, verifies password with Bcrypt, and issues a Laravel Sanctum Bearer token.

app/Http/Controllers/Api/AuthController.php (login)
AuthController.php:62 
public function login(LoginRequest $request)
{
    // 1. Health check database connection
    try {
        DB::connection()->getPdo();
    } catch (\Exception $e) {
        return ResponseHelper::error($e->getMessage(), null, 503);
    }

    try {
        // 2. Attempt authentication against 'users' table
        if (!Auth::attempt($request->only('email', 'password'))) {
            return ResponseHelper::error('Invalid credentials', null, 401);
        }

        // 3. Get the authenticated user model
        $user = Auth::user();

        // 4. Generate Sanctum Personal Access Token
        $token = $user->createToken('auth_token')->plainTextToken;

        // 5. Return standardized success response
        return ResponseHelper::success('login successfully', [
            'user'  => new UserResource($user),
            'token' => $token
        ], 200);
    } catch (Exception $e) {
        return ResponseHelper::error($e->getMessage(), null);
    }
}
4

Sending Authenticated Requests (Sanctum Guard)

GET /api/me

Clients pass the issued token in the Authorization: Bearer <token> HTTP header. The auth:sanctum middleware resolves the active user.

How Sanctum Finds the User

When you send Authorization: Bearer 1|a8f9c4...:
1. Sanctum reads the token ID before the pipe (1).
2. Sanctum computes a SHA-256 hash of the string after the pipe (a8f9c4...).
3. Queries personal_access_tokens where id = 1 and matches the hash.
4. Loads the user record (tokenable_id) and binds it to auth()->user().

5

Role-Based Access Control (RBAC)

Middleware: role:Admin,Developer,Owner

Restricted routes are guarded by the CheckRole.php middleware, comparing user roles.

app/Http/Middleware/CheckRole.php
CheckRole.php:19 
public function handle(Request $request, Closure $next, ...$roles): Response
{
    $user = $request->user();

    if (!$user) {
        return response()->json(['status' => false, 'message' => 'Unauthenticated.'], 401);
    }

    // $user->hasRole() checks user_types table for matches (e.g. 'Admin', 'Teacher')
    if (!$user->hasRole($roles)) {
        $required = implode(', ', array_map('trim', $roles));
        return response()->json([
            'status'   => false,
            'message'  => "Forbidden: This action requires the [{$required}] role.",
            'userRole' => $user->role_name,
        ], 403);
    }

    return $next($request);
}

        'employeeId'  => $this->employee_id,
    ];
}

Logout & Token Revocation

POST /api/logout

Revokes the active session token, removing the record from personal_access_tokens.

app/Http/Controllers/Api/AuthController.php (logout)
AuthController.php:113 
// Single session logout
public function logout()
{
    $user = auth()->user();
    $user->tokens()->delete(); // Purges tokens for current user
    return ResponseHelper::success('Logged out successfully', $user, 200);
}

// Global revoke (Sign out everywhere)
public function revoke_all()
{
    $result = auth()->user()->tokens()->delete();
    return ResponseHelper::success('Revoke all', $result, 200);
}

6. Novice FAQs & Concepts

Why do we hash passwords with Bcrypt?

Bcrypt is a one-way mathematical function. Once a password like Cnat@1977 is turned into $2y$12$..., nobody (not even system administrators) can reverse it back to plain text. When logging in, Laravel hashes the user's attempt and checks if both hashes match.

What is the difference between 401 Unauthorized and 403 Forbidden?

• 401 Unauthorized: "I don't know who you are" (Missing or expired Bearer token).
• 403 Forbidden: "I know who you are, but you don't have permission" (e.g., A Teacher trying to access the Admin Users list).
